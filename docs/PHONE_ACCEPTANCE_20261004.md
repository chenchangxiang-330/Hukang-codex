# 2026-10-04 手机测试清单

测试包与精确源码 SHA、SHA256、云端验证结果以 [本轮报告](./TAKEOVER_VALIDATION_20261004.md) 为准。包名 `com.hukang.local.clouddebug`，1.4.0-clouddebug / versionCode 14，需 64 位 Android。旧 `com.hukang.local` 可并存，数据不自动迁移；每次云构建临时签名不同，若提示签名不一致，先导出旧云测试版数据，再由用户决定是否卸载，不能直接清数据。

## 最短测试路径

1. 安装 APK，建立测试档案。在“我的 → 关于护康”连续点版本 7 次，诊断顶部核对源码 SHA 和设备型号/Android 版本。测试前先导出已有数据。
2. 同一张失败营养照片分别走相机和图库、手动裁剪及旋转。记录入口和时间。应出现原文、候选或明确错误；看不清的数值留空，不猜小数点。原始 OCR 允许有错字，但不能被联网文字覆盖。
3. 未配置服务时保持联网增强关闭。核对营养基准，缺字段留空或按照片人工填写，确认后保存商品；加入库存并记录一次摄入。导出本地数据 JSON，记录商品名称、基准、数值、OCR 原文、来源、独立证据、数量和日期。
4. 编辑刚保存商品，仅修改名称后保存，再导出 JSON。`ocr_raw_text`、`data_source`、`recognition_evidence_json` 应保留；不可读字段仍是 `null`，库存/摄入关联不变。
5. 在 Android 设置中强行停止云测试版，开启飞行模式并关闭 Wi-Fi，然后重新打开。再次检查商品、库存、摄入和照片，导出第二份 JSON 比较。只划掉最近任务不足以证明杀进程；不要清存储或卸载。
6. 后续配置有效 Vision 服务后，用同一图验证显式选择联网结果、保留本地 OCR 和独立 Vision 证据，再重复步骤 3–5。此项目前未执行。配料、喷码日期、条码离线重扫也须分别记录，不以两张营养图结果代替。

## 反馈材料

- 手机品牌/型号、Android 版本、诊断显示的源码 SHA。
- 最常失败的原始照片：完整包装 + 营养/配料/日期区域近照，保留原文件，不先用聊天软件压缩。确认允许用于项目内部诊断；未经明确许可不提交个人照片到公开 GitHub。
- 每张照片注明入口、时间、实际错误及人工可读的正确内容；读不清就写“不可读”。
- 每次失败后立即到开发者模式刷新并导出诊断 JSON，避免下一次扫描覆盖“最近一次”。确认保存/编辑后与离线重启后，分别导出本地数据 JSON。
- Vision 只需说明服务、endpoint 域名、model 和错误码。密钥只填在设备“在线 Provider”中，不发聊天、不放照片或 JSON、不提交 Git。选定服务后再核对兼容 endpoint/model，联网开关本身不能证明已发请求。

诊断可将问题分为照片落盘/方向/裁剪、OCR 原文、Parser、联网配置/发送/响应、确认使用/保存。收到照片和对应记录后才归因具体手机失败；本清单不是已经执行的真机测试结果。
